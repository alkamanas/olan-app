# Saha Kiti (Olan Apps mobile acceptance app)

`examples/field-kit` (moved from `mobile-react-native/tools/olan-apps-acceptance-app/`, Phase 2
server contract §7). The mobile acceptance scripts use this path.

`com.olan.mobile.acceptance` — an Olan App written only with `@olan-app/sdk` that exercises every
Phase 1 component and every platform call, so iOS and Android hosts can be accepted by hand.

- Surfaces: `app` ("Saha Kiti") and `project.widget` ("Saha özeti", reads `params.projectId`:
  open task count, a status bar chart and a Menu).
- Permissions (source `olan-app.json`): `projects:read`, `tasks:write`, `db`, `storage`, `chat:read`,
  `http:api.example.com` (**Etkileşimler → HTTP dene**, `olan.http.fetch` of
  `https://api.example.com/v1/weather`), `tasks:delete`, `projects:delete`; `sdk` `^1.1.0`,
  `minServerVersion` `0.1.0`. Every call the app makes has its permission, so
  `olan-app validate --strict` passes (SDK 1.5.1).
- `data` (version 1): collection `notes` (organization; `title` string required, maxLength 120,
  indexed; `done` boolean indexed; rules read any, update any, delete owner).
- Settings: `teamName` (string), `dailyTarget` (number), `showCompleted` (boolean), `region` (select).
- Home list → **Bileşenler** (Screen actions/subtitle, Stack gaps, Text variants/tones/weights, Badge
  tones, Button variants/disabled/loading, Menu with destructive and disabled items, List with
  badges, Table, bar and line Chart, EmptyState with action), **Form** (TextField required+error,
  multiline, secure; Select; DatePicker date and datetime; the last submission is kept in
  `olan.storage`), **Etkileşimler** (`olan.ui.confirm/prompt/menu/datePicker/share/toast`,
  `olan.navigation.push/pop`, `olan.http.fetch`), **Uzun liste** (500 rows), **Veri**
  (`olan.projects.list/get/tasks/updateTask`, `olan.chat.conversations`, `olan.settings.get`, and
  the **Kayıtlar** card), **Veritabanı** (`olan.db`).
- **Veritabanı**: `useCollection('notes')` newest first, a count Badge (`N not`, `notes.count()`), a
  Form ("Not başlığı", submit **Not ekle**), and per note a Menu "Not işlemleri" with **Tamamlandı
  işaretle** (`update` with revision) and **Sil** (`olan.ui.confirm` destructive, then `delete`).
  The note the other user created (in fixtures) is protected by `delete: owner` → `forbidden_record`.
- **Veri → Kayıtlar** (the `app` surface's `params.projectId` when the host passes one, otherwise
  the first project from `olan.projects.list()`; no fixed id, real servers use UUIDs; with the
  fixtures that is `p-saha`; the card subtitle names the project): **Görev oluştur** (`createTask`, default work package;
  the task is kept in `olan.storage` `createdTask` and shown), **Oluşturduğum görevi sil**
  (`deleteTask` with the current revision, after a destructive confirm), **Varsayılan iş paketini
  sil** (`deleteList` of the `isDefault` list → must fail with `forbidden_record`), **Boş iş paketini
  sil** (`deleteList` of an empty non-default list → archived).
- Every Phase 1b error is shown as `<label>: <code>: <message>` in the screen's result text and as
  `olan.ui.toast({ text: '<code>: <message>', tone: 'danger' })`.
- The home screen shows `useTheme()`, `useLocale()` and `usePlatform()` so a theme switch on the
  device is visibly delivered to the app.

The packaged versions are generated by `mobile-react-native/tools/olan-apps-mock-server/build-packages.sh` from
`olan-app.json` (1.0.0) and the test version `fixtures/versions/1.1.0/olan-app.json` (1.1.0: the
same manifest plus `users:read`, which the app does not call; it only makes the update ask again):

| package | manifest | permissions |
|---|---|---|
| 1.0.0 | `olan-app.json` | source − `tasks:delete` − `projects:delete` (deletes answer `permission_denied`); `http:api.example.com` included, so **HTTP dene** works |
| 1.1.0 | `fixtures/versions/1.1.0/olan-app.json` | 1.0.0 + `users:read` (exactly one extra: re-consent asks only for it) |
| 1.2.0 | the 1.1.0 manifest, version 1.2.0 | 1.1.0 + `tasks:delete` + `projects:delete` (re-consent with the delete group) |

Up to SDK 1.5.0 the 1.1.0 package added `http:api.example.com`; the source now asks for it (decision 5), so
the re-consent step uses `users:read`. `fixtures/versions/` is not mock data (only `fixtures/*.json`
is); `tests/app.test.ts` checks that the 1.1.0 manifest is the source plus that one permission and
that a person who consented to 1.0.0 is asked only for `users:read`.

```sh
npm install                      # installs @olan-app/sdk and @olan-app/cli from npm
npx olan-app validate --strict
npx olan-app test                # tests/app.test.ts with fixtures/ (projects, chat, http, db)
npx olan-app pack --dev-sign     # dist/com.olan.mobile.acceptance-1.0.0.olanapp, development key

# The 1.1.0 test package (re-consent), from a copy so the source stays 1.0.0:
cp -R . /tmp/field-kit-1.1.0 && cp fixtures/versions/1.1.0/olan-app.json /tmp/field-kit-1.1.0/olan-app.json
(cd /tmp/field-kit-1.1.0 && npx olan-app pack --dev-sign)   # dist/com.olan.mobile.acceptance-1.1.0.olanapp
```

On the Mac the mobile acceptance flow does not build this directly: `mobile-react-native/tools/olan-apps-mock-server/build-packages.sh` copies it into
`.work/`, tests and packs it (trusted, stranger-signed, unsigned, 1.1.0 and 1.2.0).
